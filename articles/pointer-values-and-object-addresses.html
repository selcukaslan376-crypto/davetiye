Pointer Values, Object Addresses, and Dereferencing in C

A pointer is an object with a type and a stored value—not a synonym for the object it may designate. That distinction makes invalid states easier to recognize.

Pointer discussions become confusing when “pointer,” “address,” and “the pointed-to object” are used as interchangeable names. They are related, but they are not the same thing. A declaration creates a pointer object; evaluating that object produces a pointer value; a valid pointer value may designate an object or function. Dereferencing is an operation performed with that value.

Scope and terminology

This is original introductory sample content for C99 and C11. It describes ordinary object pointers and deliberately avoids treating a machine address as the complete C model. It is not a formal quotation from the ISO C standard.

Note

Implementations often represent a pointer as a numeric virtual or physical address, but portable C describes pointer values and the objects or functions they designate. The representation is an implementation concern.

Pointer objects and pointer values

An object is a region of data storage whose contents can represent values. If the object has a pointer type, it is a pointer object. Like an integer object, it has its own storage and lifetime.

pointer-object.c
int temperature = 24;
int *sensor = &temperature;

int measured = *sensor;

Here, temperature is an int object. sensor is a separate object of type “pointer to int.” The initialization stores a pointer value in sensor. That value designates temperature. The expression *sensor then designates the int object.

Two pointer objects can store equal pointer values. They remain two objects with separate storage:

two-pointer-objects.c
int value = 5;
int *first = &value;
int *second = first;

*second = 6; /* Modifies value. */
first = NULL; /* Does not change second. */

Assigning NULL to first replaces the value stored in that pointer object. It does not modify second and does not modify value.

The address-of operator

The unary & operator produces a pointer to its operand in the ordinary object case. Its result has a type derived from the operand: applying & to an int object produces a value of type pointer to int.

address-of.c
int counter = 0;
int *counter_address = &counter;
int **pointer_address = &counter_address;

&counter and &counter_address have different types and designate different objects. The first points to the int; the second points to the pointer object. Adding another * to a declaration is not decoration—it adds another level of indirection.

Tip

When reading pointer code, name every object and write down the type of each full expression. This is usually faster than reasoning from punctuation alone.

The indirection operator

The unary * operator uses a pointer value to designate the object or function to which it points. When p holds a valid pointer to an int, *p is an lvalue designating that int. It may be read, and it may be written if the lvalue is modifiable.

indirection.c
int mode = 1;
int *selected = &mode;

int old_mode = *selected; /* Read mode. */
*selected = 2;            /* Write mode. */

Indirection is only meaningful when the pointer value satisfies the requirements of the operation: it must designate a suitable live object or function, with the necessary alignment and access. A declaration such as int *p establishes a pointer type; it does not prove that the current stored value is safe to dereference.

Null, uninitialized, and dangling pointers

Null pointers

A null pointer value is guaranteed not to compare equal to a pointer to an object or function. It is useful as an explicit “no object” state. The macro NULL expands to an implementation-defined null pointer constant suitable for initialization and comparison.

null-check.c
int *sample = NULL;

if (sample != NULL) {
    use_value(*sample);
}

Dereferencing a null pointer has undefined behavior. Checking first is useful only if the pointer cannot become invalid between the check and the use—a concern in concurrent code.

Uninitialized pointers

An automatic pointer object without an initializer has an indeterminate value. It must be assigned a valid value or a null pointer value before code evaluates it as a pointer.

uninitialized.c
void bad_example(void)
{
    int *reading;
    *reading = 10; /* Undefined behavior; reading was not initialized. */
}

Do not expect an uninitialized pointer to begin as null. Static-storage objects receive zero initialization, but an ordinary uninitialized automatic object does not receive that guarantee.

Dangling pointers

A pointer becomes dangling when the lifetime of its designated object ends while a copy of the pointer value remains. Returning the address of an automatic local object is a common example:

dangling.c
int *wrong(void)
{
    int temporary = 42;
    return &temporary;
} /* temporary's lifetime has ended. */

A dynamically allocated object also reaches the end of its lifetime when it is deallocated. Copies of pointers into that allocation must not be dereferenced afterward. Assigning NULL to one pointer variable does not update other aliases.

Warning

A non-null pointer is not necessarily valid. Null checking detects one invalid state; it does not detect uninitialized values, expired lifetimes, out-of-bounds values, misalignment, or incompatible access.

Why an arbitrary integer is not a valid pointer

C provides explicit conversions between integer and pointer types, but those conversions are implementation-defined outside the special rules for null pointer constants. Converting an arbitrary number to int * does not create an int object at that location, establish alignment, begin an object lifetime, or make the resulting pointer safe to dereference.

not-portable.c
#include <stdint.h>

uintptr_t raw = 0x40000000u;
volatile unsigned int *reg =
    (volatile unsigned int *)raw;

This pattern may be meaningful in a specific embedded implementation where the memory map, compiler, ABI, and device documentation jointly define the behavior. It is not portable evidence that every integer represents a usable address. Hardware register access should be isolated behind platform-specific definitions and justified by that implementation’s guarantees.

Printing object pointer values with %p

The printf conversion specifier %p expects a corresponding argument of type void *. For an object pointer, explicitly convert to void * so that the variadic call supplies the expected type.

print-pointer.c
#include <stdio.h>

int value = 17;
int *pointer = &value;

printf("pointer = %p\n", (void *)pointer);

The textual representation is implementation-defined. Do not assume hexadecimal formatting, a fixed width, or a value suitable for parsing back into a usable pointer. The portable conversion between void * and other object pointer types is why this pattern applies to object pointers; function pointers require implementation-specific consideration.

A compact working model

  1. A pointer object has its own storage, type, value, and lifetime.
  2. A pointer value can designate an object or function, represent a null pointer, or be unusable for the intended operation.
  3. &object produces a pointer value for that object in ordinary cases.
  4. *pointer designates the target only when the pointer value is valid for that operation.
  5. Null, uninitialized, and dangling are different states; a null check cannot validate every pointer.
  6. An integer-to-pointer cast does not, by itself, create a valid object access.
  7. Print object pointers with %p and a void * argument.
