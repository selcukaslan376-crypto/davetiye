Understanding const in C: Qualified Types, Objects, and Modifiable Lvalues

A careful introduction to what const qualifies, what an expression allows, and why pointer declarations require reading from the identifier outward.

The word const is often introduced as meaning “this variable cannot change.” That shortcut is useful for a first encounter, but it stops being reliable once pointers, function interfaces, or casts enter the program. In C, const is a type qualifier. The useful question is not simply “is this variable constant?” but “which type is qualified, which object does an expression designate, and is the lvalue used for the modification modifiable?”

Scope of this introduction

This article is original introductory sample content for a growing knowledge base. It uses the vocabulary of C99 and C11, but it is not a quotation from the ISO C standard and does not replace the normative text. The examples focus on ordinary object pointers and scalar objects so that the central distinctions remain visible.

Note

C and C++ share much of the surface syntax shown here, but their type systems and rules are not identical. The statements in this article are about C.

Qualified types and objects

A type such as const int is a const-qualified version of int. When an object is defined with that type, the object is not modifiable by a C program after initialization.

const-object.c
const int sample_limit = 64;

/* Reading the value is ordinary and valid. */
int local_limit = sample_limit;

/* Constraint violation: sample_limit is not a modifiable lvalue. */
sample_limit = 128;

The last assignment requires a diagnostic from a conforming implementation; it is not made acceptable by the fact that the object occupies storage. Storage and permission to modify through a C expression are separate concerns.

Qualification can also appear inside aggregate types. A structure or union is not a modifiable lvalue when one of its members has a const-qualified type, including through nested aggregate membership. This prevents whole-object assignment from becoming a back door to overwrite a const-qualified subobject.

The role of a modifiable lvalue

An lvalue is an expression that designates an object. Not every lvalue is modifiable. In the common scalar case, a modifiable lvalue must designate an object through a type that is not const-qualified, and it must satisfy the language’s other restrictions on modifiable lvalues.

This vocabulary explains why the left side of an assignment matters. Consider a non-const object viewed through two differently qualified pointer types:

two-views.c
int reading = 12;
int *writable = &reading;
const int *observed = &reading;

*writable = 13;  /* Valid: reading is an int object. */
int copy = *observed; /* Valid: reading through observed. */
/* *observed = 14;  Not allowed through this lvalue. */

The pointer observed does not transform reading into a const-defined object. It provides an access path whose pointed-to type is const-qualified, so an assignment through *observed is not allowed. Another legitimate, unqualified access path may still modify the original int.

Tip

Separate two questions: “Was the object defined with a const-qualified type?” and “Does this particular lvalue have a const-qualified type?” They often have the same answer, but pointer conversions can make them differ.

The pointer object and the pointed-to object

A pointer declaration can qualify the pointed-to type, the pointer type, or both. Read from the declared identifier outward and notice where const appears relative to the *.

DeclarationPointer objectPointed-to access
const int *pp may be reassigned.*p is not modifiable through p.
int * const pp may not be reassigned after initialization.The pointed-to int may be modified through p.
const int * const pp may not be reassigned.*p is not modifiable through p.
pointer-qualification.c
int first = 10;
int second = 20;

const int *view = &first;
view = &second;             /* Valid: view itself is not const. */

int * const fixed = &first;
*fixed = 11;             /* Valid: first is modifiable. */
/* fixed = &second;         Not allowed: fixed is const. */

In int * const fixed, fixed is itself a const-qualified pointer object. Its stored pointer value cannot be replaced through an assignment to fixed, but the int it designates is not const-qualified through *fixed.

Casting away const does not change the object

An explicit cast can produce a pointer whose pointed-to type is no longer const-qualified. It cannot retroactively change how the object was defined. Whether modification is valid still depends on the actual object.

cast-away-const.c
const int fixed_value = 7;
int *attempt = (int *)&fixed_value;

*attempt = 8; /* Undefined behavior. */

The cast suppresses the type-system obstacle at that expression. The object fixed_value was still defined with a const-qualified type, so attempting to modify it produces undefined behavior. A system may place such an object in read-only storage, but a visible crash is only one possible outcome; undefined behavior does not require one.

Now compare that with an object that was not defined as const:

underlying-object.c
int value = 7;
const int *view = &value;
int *original_kind = (int *)view;

*original_kind = 8; /* Valid: value was defined as int. */

This modification is valid because the underlying object is a modifiable int. Even so, routinely casting away qualifiers is a design warning: the caller may not know whether a pointer originally referred to a const-defined object.

Warning

A cast answers a type-conversion question. It does not grant write permission, make read-only storage writable, or extend an object’s lifetime.

Using const in interfaces

A pointer to const-qualified data is useful when a function reads an object without modifying it through that parameter. It communicates intent to the caller and lets the compiler reject accidental assignments within the function.

read-only-interface.c
#include <stddef.h>

long sum_samples(const int *samples, size_t count)
{
    long total = 0;

    for (size_t i = 0; i < count; ++i) {
        total += samples[i];
    }

    return total;
}

This interface does not promise that no other part of the program will modify the array concurrently or later. It says that this function’s access through samples is read-only. Synchronization and lifetime remain separate responsibilities.

Adding qualification at the pointed-to level is commonly safe when passing an int * to a function expecting const int *. Silently removing it in the other direction would discard a protection, so a conforming implementation must diagnose the constraint violation.

A compact working model

  1. const qualifies a type; first identify exactly which type.
  2. An object defined with a const-qualified type must not be modified.
  3. A pointer to a const-qualified type restricts modification through that pointer; it does not necessarily mean the underlying object was defined as const.
  4. A const-qualified pointer prevents reassignment of the pointer object, not necessarily modification of the pointed-to object.
  5. Casting away const changes the expression’s type, not the definition or mutability of the underlying object.
