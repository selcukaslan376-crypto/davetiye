About

Engineering close to the hardware.

I work across firmware, embedded Linux, device communication, and test systems, with modern C at the center of my practice.

Biography

I am an Embedded Software Engineer with approximately two years of professional experience developing embedded systems and firmware. My primary focus is Embedded C using modern language standards, especially C99 and C11.

My day-to-day engineering work includes low-level firmware, pointer-oriented design, static and dynamic memory concepts, data structures, bitwise programming, hardware abstraction, protocol implementation, and device integration. I have developed for STM32, PIC16, and PIC32 microcontrollers and worked with UART, SPI, I2C, CAN, and MODBUS communication.

Measurement and test systems have been a recurring context for that work. My experience includes ADC data acquisition, signal processing and filtering, calibration algorithms, EEPROM-backed parameter management, debugging, integration, and system verification. Beyond firmware, I work with embedded Linux and Buildroot, cross-compile target software, build Qt/QML HMIs, and create automation and test interfaces with Python, Shell, and C#/.NET.

I am also pursuing an M.Sc. in Geomatic Engineering. My current academic direction centers on Multi-GNSS positioning and sensor-fusion algorithms, including GPS, GLONASS, and Galileo. This is ongoing graduate research; no completed thesis result is implied.

Why I write

C is compact on the page, but its precise model is not always compact in the mind.

I write to examine details that are important in real programs yet frequently misunderstood or passed over: type qualifiers, pointer semantics, object lifetimes, memory management, undefined behavior, and the terminology used to reason about the language.

The aim is not to turn every explanation into a standards-lawyer exercise. It is to build accurate mental models, distinguish similar-looking concepts, and connect that precision to code that runs on constrained systems.
